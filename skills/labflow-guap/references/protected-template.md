# Защищённый шаблон ГУАП

## Источник и границы

`assets/guap/titlepage.typ` и `assets/guap/gost.typ` взяты побайтово из выполненной лабораторной `pank-suai/mat_osn_lab_1`, каталог `docs/lib`. Происхождение и SHA-256 сохранены в `assets/guap/source.json`. Это выбранный пользователем образец, а не заявление о соответствии любой будущей методичке. Исходную лабораторную не изменять.

Локальные iCloud-копии `lab_template` при чтении оказались пустыми; публичные raw-ссылки ветки main были недоступны. Поэтому использована разрешённая пользователем альтернатива: непустой шаблон выполненной лабораторной. Нельзя подменять его заново придуманной вёрсткой или универсальным `labflow-typst`.

## Контракт редактирования

- В созданном шаблоне агент вручную редактирует только `index.typ`: содержание отчёта.
- Реквизиты титульника меняет только команда `title` через входной JSON с разрешёнными полями. JSON запроса можно подготовить вне каталога шаблона; он не является файлом титульника.
- Служебные Typst-файлы, сохранённые реквизиты и контрольные суммы обновляет только скрипт. Запрещено редактировать их напрямую, пересчитывать lock для сокрытия изменения, удалять проверку или обходить `build` прямой компиляцией.
- Нельзя менять ГОСТ-поля, шрифт, блоки подписей, линии, положение элементов титульника, добавлять логотипы или новый дизайн.
- Не переносить старые ФИО, группу, кафедру и дату. Использовать подтверждённые пользователем или текущим заданием значения; отсутствующие реквизиты не угадывать.
- Сценарий «без титульника» не превращать в сценарий с титульником. Существующий курсовик автоматически не мигрировать.
- Изменение самого образца возможно лишь по отдельному явному запросу пользователя; не как побочный эффект оформления отчёта.

## Команды

Определить `<skill-root>` по `skill_view(name='labflow-guap')`. Все команды выполнять через `terminal`, сохраняя пути с пробелами как один аргумент.

```text
python3 <skill-root>/scripts/guap_template.py init <project>
python3 <skill-root>/scripts/guap_template.py title <project> --data <metadata-request.json>
python3 <skill-root>/scripts/guap_template.py check <project>
python3 <skill-root>/scripts/guap_template.py build <project>
```

`init` создаёт шаблон без перезаписи существующей работы. Если `index.typ` уже существует, его содержимое сохраняется; существующий защищённый каталог не перезаписывается. Структура:

```text
<project>/
  index.typ              # единственный редактируемый вручную файл шаблона
  .guap/
    titlepage.typ        # исходный титульник
    gost.typ             # исходные правила оформления
    main.typ             # фиксированная точка сборки
    metadata.json        # изменяется только командой title
    lock.json            # изменяется только скриптом
  report.pdf             # результат build
```

`title` принимает данные, не Typst-код. Разрешённые поля: `title`, `authors`, `teachers`, `date`, `education`, `department`, `position`, `documentName`, `group`, `city`, `object`. `authors` и `teachers` — массивы строк, остальные — строки; `date` — календарная дата `YYYY-MM-DD`. Можно передать только изменяемые поля. Перед сборкой обязательные реквизиты должны быть заполнены; не заменять их выдуманными значениями ради успешного запуска.

`check` проверяет целостность без исправления и перебазирования. `build` выполняет проверку, компилирует фиксированную точку входа и повторно проверяет целостность. Результат — `report.pdf`; отсутствие нового успешного результата нельзя выдавать за выполненную сборку.

Перед первым использованием прочитать `--help`; список аргументов и диагностику брать из фактического скрипта, не придумывать новые флаги.

## Проверки

Через `terminal` выполнить:

```text
python3 <skill-root>/scripts/test_guap_template.py
```

Дополнительно на временном проекте проверить реальную компиляцию Typst и визуально первую страницу. Тестовые имена и реквизиты обозначать как демонстрационные; их нельзя переносить в учебный отчёт пользователя. После изменения реквизитов проверять переносы и сохранение титульника на одной странице; при переполнении не уменьшать шрифт и не переписывать защищённый шаблон.

## Что именно защищено

Это fail-closed контроль целостности в штатном workflow, а не sandbox против злоумышленника с правом записи в скрипт и файлы. Он выявляет случайные или несанкционированные ручные правки и останавливает штатную сборку. Для абсолютного запрета потребовался бы отдельный доверенный сервис/пользователь ОС с недоступными агенту правами записи; такой сервис здесь не разворачивается.
