# Профили учебных работ

Через `terminal` вызовите `python3 <guap-skill-root>/scripts/work_profiles.py list`.
Корень берётся из загруженного `labflow-guap`. Python 3.10+, стандартная библиотека;
для реальной PDF-сборки — Typst. Конкретные источники и правила авторизации не читаются.

## Выбор и приоритеты

- `physics`: протокол впереди, данные/схема/расчёты/погрешности/вывод;
  таблицы 16 pt, результаты до десятых, пример каждой формулы.
- `calculation`: краткая расчётная, таблицы 14 pt, без списка материалов,
  пример каждого типа расчёта; точность задаётся методичкой.
- `coursework`: введение, предметная область, проектирование, реализация,
  заключение, источники и приложения; первый уровень с новой страницы.
- `lecture`: структура конспекта без автоматического PDF/титульника/кода.

Это редактируемые **профильные значения по умолчанию**, не универсальные нормы вуза.
Порядок: defaults → текущая методичка → явная поправка пользователя. Если методичка
и пользователь конфликтуют, contract становится blocked; принятую осознанную
поправку нужно явно включить в accepted_exceptions. Исторические заметки о
преподавателе не превращаются в текущую методичку. При переносе образца переносится
структура/стиль, но не его старые автор, данные, технический текст и результаты.

Через `terminal`:

```text
python3 <guap-skill-root>/scripts/work_profiles.py compile --profile physics --output-dir <workspace>/context/profile
python3 <guap-skill-root>/scripts/work_profiles.py compile --profile coursework --scope publication --domain code --overrides <workspace>/context/profile-overrides.json --output-dir <workspace>/context/profile
```

Каталог вывода должен быть новым. Существующий контракт не перезаписывается;
после изменения создайте новую версию каталога, обновите импорт и candidate scope.
Нельзя писать в `.guap` или через symlink в любом предке выходного пути.
Для системных alias (например, macOS `/var`) caller сначала явно определяет
канонический рабочий каталог, а затем передаёт путь внутри него; компилятор
не следует произвольным ссылкам молча. Исходный защищённый шаблон не изменяется. Для physics
сохраняется именно назначенный физический шаблон, а не автоматическая миграция на
универсальный лабораторный титульник.

## Исходники решений

`--overrides` принимает строгий JSON; неизвестные поля, неподходящие типы,
повторные ключи и исключения без реального конфликта отвергаются. Пример:

```json
{
  "methodology": {
    "sections": {"value":["Исходные данные","Решение","Вывод"],"source":"inputs/current-method.pdf","locator":"страница 2, требования"},
    "table_pt": {"value":14,"source":"inputs/current-method.pdf","locator":"страница 3"}
  },
  "user": {
    "table_pt": {"value":16,"source":"context/current-correction.txt","locator":"строка 1"}
  },
  "accepted_exceptions": ["table_pt"]
}
```

Компилятор проверяет форму атрибуции, но не утверждает, что прочитал документ
по полю source. Агент проверяет оригинал и включает его в Labflow source-map/inputs.
Все правила и выбранные источники попадают в `contract.json` (`rules/provenance`).
При неразрешённом конфликте код выхода ненулевой и `style.typ` не создаётся.

## Фазы и применение

`--scope full|revision|publication`, `--format pdf|notes|csv`, повторяемый
`--domain code|math` формируют `plan.phases`. Revision не добавляет несвязанные
code/math/review автоматически. Если правка меняет математику, укажите math.
CSV не добавляет report; notes не добавляет PDF. Full/publication требуют context,
verify и независимый review. Скопируйте **явные** plan/scope в элемент batch-контракта
общего Labflow; sources/outputs назначает caller, профиль не угадывает пути.

Для PDF создаётся `style.typ` с `profile-style`: TNR, body/table font sizes и
pagebreak для первого уровня coursework. Подключите его через импорт и
`#show: profile-style` только в разрешённом авторском `index.typ`, сохранив
действующий template wrapper и реквизиты. Это не инициализатор проекта и не право
редактировать `.guap`, layout или protected metadata. Выполните штатный template
check/build. Если назначенный шаблон требует другого способа применения стиля,
сначала согласуйте конфликт, не обходите его защиту.

Остальные rules (секции, округление, примеры, вывод, подписи/ссылки) — контракт
для специализированных фаз и academic review, а не автоматический переписчик
учебного текста. `rounding_decimals` управляет **отображением**, не точностью
промежуточных вычислений. Таблица/рисунок по-прежнему требуют подписи, метки и
явной ссылки. Служебные логи остаются вне сдаваемого текста.

## Приёмка

1. Проверьте ready/blocked, профиль, scope, реальные источники каждого override.
2. Примените контракт в соответствующих фазах; соберите требуемый артефакт.
3. Сравните шрифты/таблицы, секции, нотацию, округление, примеры и вывод с contract.
4. Проверьте все требуемые страницы, не только контактный лист.
5. Включите profile contract/style и текущую методичку в candidate inputs общего
   Labflow; для полного кандидата обязательны независимые review и fresh fingerprint.
6. Никакой отправки в кабинет, cron или авторизации из профиля не происходит.

`tests/test_work_profiles.py` проверяет различия профилей, приоритеты/конфликты,
ограниченный scope, отказ при защищённом destination, настоящий Typst PDF и размеры
его текста. Синтетические fixtures не содержат персональных учебных материалов.
